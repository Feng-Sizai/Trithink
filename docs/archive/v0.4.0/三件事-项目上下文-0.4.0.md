# 三件事：项目上下文与当前基线

归档日期：2026-10-19（Asia/Shanghai）  
当前程序版本：0.4.0  
用途：供“三件事”共享项目的成员和后续开发对话了解已经确认的需求、实现位置和验证边界。

这是一份根据需求讨论与实际源码整理的交接记录，不是逐字聊天导出。对话中未保留的选项说明不作推测。压缩包与本说明不包含使用者的真实项目、速写、作息记录或账号凭据。

## 一、产品目标与协作约定

面向需要管理课程、考试、实践活动等事项的大学生，把事情拆小，并让今日页面只突出眼前最值得做的三件事。程序离线使用、数据保存在本机，结构应便于以后修改 UI 和扩展功能。

用户明确要求：不确定的问题应多询问，不要擅自决定。已经确认的功能与界面细节应保留；普通代码整理不得顺带取消功能或改变外观。

账号、共享项目进程、云同步只预留接口，本版不增加登录界面或开启远程服务。把开发资料放进 ChatGPT 共享项目，不代表应用内已经支持多人共享任务数据。

## 二、已确认的功能规则

### 1. 项目、阶段、任务

- 结构为“项目 > 阶段 > 任务”。可建立多个项目，项目下添加阶段，阶段继续拆为小任务。
- 阶段可以自由上下排序，不设必须先完成前一阶段的限制。
- 项目设置紧急程度和重要程度；阶段、任务可单独设置星级，否则沿用上一级。重要程度来自项目。
- 项目、阶段、任务支持截止日期；下级未单独填写时沿用上一级日期，单独设置后使用自己的日期。
- 未拆阶段的项目本身就是可执行事项，应按优先级自动参与今日计划。
- “我的项目”只列未全部完成的项目；完整项目在已完成记录中查看。

### 2. 优先排序

排序严格依次为：紧急程度（星级）> 重要程度 > 截止时间。

| 星级 | 含义 |
| --- | --- |
| ★ | 缓 |
| ★★ | 急 |
| ★★★ | 立刻 |

先比较星级，再比较项目重要程度（高、中、低），最后按截止日期从近到远排序；无日期排在有日期之后。星级展示统一使用“★：缓 / ★★：急 / ★★★：立刻”。

### 3. 今日计划：自动与手选

- 首页最多展示三项任务。
- 自动模式按上述顺序，从当天自动队列中取前三项。未拆阶段的项目自动参与；其余事项可以加入或移出今日队列。
- 自动模式的完成卡片先保留，点击“继续下一个”再补位。
- 手选模式从全部任务中明确选择最多三项，回首页拖拽任务条改变顺序；也支持把手与上下键。
- 两种模式各自保存安排，切换不会覆盖另一模式。手选完成后不自动补入其他任务，也不重排已有位置。
- 今日安排按日期保存，新日期不会直接沿用前一天的手选列表。

### 4. 已完成记录

- 按完成日期从近到远显示。
- 项目全部阶段和任务完成后，项目完成时间取最后一项完成时间，并合并显示为一条项目记录。
- 项目尚未全部完成时，对应日期下只显示已完成的阶段或任务；完整阶段可以合并显示。
- 完成时间保留 UTC 时间戳，界面按电脑本地日期分组。旧版未知日期不能虚构补齐。
- 撤销完成需要清理相应完成时间并同步父级状态。

### 5. 速写本

- 支持标题、副标题、正文以及加粗、斜体、项目符号、编号等常用格式。
- 草稿与已保存的速写记录分开；草稿自动保存，点击“保存速写”收录到历史。
- 历史按创建日期收录，支持查看、编辑、删除、置顶；置顶按钮位于删除按钮左侧。
- 置顶记录显示在最上方；仅删除历史页标题下的说明小字，不能删掉置顶与删除功能。
- 编辑器销毁、切换页面及导入备份时，应正确处理草稿与延迟保存，避免覆盖其他记录。

### 6. 今日作息与日历

- 每个日期保存“计划入睡时间”和咖啡、奶茶、其他三类饮品杯数。
- 饮品每次确认后加一杯；先提示“是否记录新摄入一杯（种类），确认后不可取消”，提供确认与取消。已确认数量不能减掉。
- 历史计划入睡时刻允许补记与修改；历史饮品也只允许追加。
- 日历是独立页面，以月视图呈现日期、入睡时刻、饮品和事件，可切换月份或回到今天。
- “今日作息”和“日历”两个页面顶部都显示统计栏。
- 三天平均统计前三个自然日，不含今天；使用计划入睡时刻，不增加实际睡眠时长或起床记录。三天都填好后才显示均值，否则显示记录进度。
- 入睡平均值应连续处理午夜，例如 23:30、00:30、01:00 的平均值为 00:20。
- 七天饮品累计包含今天，按三种饮品分别累计。

### 7. 日历事件与项目关联

- 每个日期可添加多个事件标注，设置事件名称与星级。
- 保存事件后询问是否同步到“我的项目”，取消则仅保留日历事件。
- 每次同步由用户选择新建独立项目，或加入已有项目；加入已有项目时继续选择新阶段或新任务，新任务需选择所属阶段。
- 新建项目时选择重要程度；事件日期作为对应项目、阶段或任务的截止日期。
- 保持单向关联：日历事件改名、改星级或改日期，会更新对应项目事项；项目侧编辑不反向改变日历。
- 删除已经同步的事件时，每次都询问是否同时删除对应项目事项；不能默认为删除项目内容。
- 删除父事项后应清理失效关联，不能使保留下来的日历事件崩溃。

## 三、已经确认的 UI

- 绿色“三”图标，浅色背景与柔和绿色按钮，延续现有视觉风格。
- 左侧顺序：今日计划、我的项目、日历、其他功能。
- “其他功能”悬停显示浮窗，包含全部任务、速写本、今日作息；支持点击和键盘操作。
- 浮窗应位于速写本编辑区上层，不能被编辑区遮挡；三个入口都要可点击。
- 项目卡片标题下显示“首要任务”，展示当前优先事项名称；“阶段数”与“任务数、完成数”在同一行。
- 项目页说明为“项目>阶段>任务”；卡片按钮为浅绿色“查看子阶段与进度”，附向右指的小手。
- 重要程度使用醒目标识，“高 / 中 / 低”的字号与“重要程度”一致。
- 返回使用左尖括号样式；阶段调序使用粗箭头，按最后确认的源码尺寸保留。
- 紧急程度与截止时间的表单标签同高，下拉框与日期输入框上下对齐、等高。
- 侧栏摘要分三行：已完成 n 项任务、计划入睡时间、饮品摄入；品牌副标题在“一件件完成”前换行。

## 四、代码结构与开发入口

| 文件或目录 | 职责 |
| --- | --- |
| src/core.js | 数据结构、校验、优先级、完成时间、今日模式、速写规则 |
| src/calendar-core.js | 日期、午夜均值、作息统计、事件与项目单向关联 |
| src/storage.js | 本机保存、有效副本、导入导出 |
| src/integrations.js | 本地存储及未来账号、共享接口；远程提供器当前为 null |
| src/editor.js | 富文本编辑与内容清理 |
| src/shell.html | 导航、固定骨架与安全策略占位 |
| src/styles.css / src/calendar.css | 原有界面与日历视觉样式 |
| src/app/ | 状态、记录、页面、今日模式、速写、日历、浮窗及弹窗分区 |
| src/app.js | 事件入口、跨日处理、首次渲染 |
| build.config.cjs | 源码与样式组装顺序 |
| scripts/ | 检查、构建、预览与桌面准备 |
| tests/ | 规则、保存、构建、桌面权限边界与升级契约检查 |
| desktop/ | Windows 窗口、安装配置、图标与锁定依赖 |

前端无运行时 npm 依赖，最终 HTML 自包含，不依赖 CDN。应用分区在构建时进入同一个私有闭包，新增分区要同步注册构建顺序。维护源码，不能直接修改 dist 或桌面生成页面。

常用命令：`npm run check`、`npm run build`、`npm run desktop:setup`、`npm run desktop:package`。前端需要 Node.js 18 或更新版本；桌面工具需要 Node.js 22.12 或更新版本。桌面依赖锁定 Electron 44.8.0 和 electron-builder 26.15.3。

## 五、数据与安全边界

- 数据版本仍为 schemaVersion 1；兼容旧文件：补充缺失的 calendarEvents、项目 due 及今日模式等可选字段。
- 桌面资料目录为当前用户 `%APPDATA%\ThreeThings`，应用名 ThreeThings、来源协议 three-things 和应用 ID 保持稳定。
- 普通数据键为 three-things-trial:v1；日历示例预览使用独立键 three-things-calendar-preview:v1，不能读取或覆盖真实记录。
- 个人记录及 JSON 备份未加密，应由使用者自行保管；共享档案不携带这些记录。
- 标题等纯文字转义，导入数据按类型、长度、日期、ID 和容量校验；笔记仅保留允许标签。
- 保留 CSP、桌面沙箱、上下文隔离和 Web 安全，关闭 Node 集成、任意外部导航与新窗口。

## 七、共享成员如何接手

先阅读本文件，再查看完整源码索引或解压共享包。需要改 UI 时从样式与对应 app 分区入手；改业务规则时优先修改纯规则模块并运行检查。

不要用个人真实记录做自动测试。新增账号或多人共享属于后续独立需求，应先确认权限、冲突处理与数据迁移方式，不能因为项目资料已经共享就直接开启应用内联网同步。

本地生成共享文件不等于已经上传到 ChatGPT 项目。上传和共享可见状态应以“三件事”项目来源列表实际显示的文件为准。
