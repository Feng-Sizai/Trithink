# 三件事：需求讨论与设计演进记录

整理日期：2026-10-19。以下为已经明确提出并采纳的设计决定，不是逐字聊天记录。

## 1. 从需求梳理到页面草图

最初目标是为大学生管理课程复习、实践策划等多个项目。逐步确认项目可以分阶段，阶段继续拆任务；阶段可以自由排序。今日页面只突出三个任务，以减少同时面对太多待办的负担。

紧急程度最终等同于优先级，并以一星、两星、三星表示。重要程度独立设置，只在星级相同的情况下参与排序。最终顺序为“紧急程度（星级）>重要程度>截止时间”。星级语义固定为缓、急、立刻。

## 2. 项目卡片与细节调整

- 项目大标题下需要看到当前优先事项名称，后来文案统一为“首要任务”。
- “1 个子阶段”改为“1 个阶段”，阶段数量和“任务数·已完成数”合并到同一行。
- 重要程度采用醒目标识，程度值与标签同字号。
- 入口改成浅绿色“查看子阶段与进度”，右侧为指向右方的小手。
- 项目页副标题改为同一行“项目>阶段>任务”。
- 返回箭头改成简洁左尖括号；阶段上下调序按钮的箭头经过多次粗细与尺寸调整，最终按当前源码保留。
- 编辑表单中紧急程度、截止时间的标签和输入框需要同高对齐。

## 3. 作息与速写本

新增今日作息：计划入睡时刻与咖啡、奶茶、其他饮品计数。饮品追加必须先确认，确认后不能撤销。侧栏底部改为已完成数量、入睡计划、饮品三行摘要。

新增速写本：支持标题、副标题、正文及常用格式。继续加入按日期收录的历史、删除和置顶，置顶位于删除左侧。后来仅删除历史页的说明小字，相关功能必须保留。

## 4. 完成历史与代码整理

完成记录按日期查看。父项目全部完成后取最后子项的完成时间；部分完成时保留阶段或任务记录。旧版没有的完成时间不补造。

代码整理要求保留当时全部功能与 UI，分离纯数据规则、存储、编辑器、页面与事件入口，便于打包和后续扩展。桌面图标使用现有绿色“三”，数据保存在本机，账号和共享仅预留接口。

## 5. 今日计划的两种模式

在原自动优先顺序之外，增加手选模式。从全部任务选择最多三项，再通过拖拽调整执行顺序。自动与手选的安排独立保存；手选完成后不自动补位，也不改变其他手选任务的位置。

## 6. 0.4.0 日历需求的逐项确认

| 问题 | 最终确认 |
| --- | --- |
| “平均睡眠时间”是什么 | 平均计划入睡时刻，例如 00:30，不是睡眠时长 |
| 日历放哪里 | 左侧独立页面 |
| 统计使用计划还是实际时刻 | 使用现有计划入睡时间 |
| 三天范围 | 前三个自然日，不包含今天 |
| 七天饮品范围 | 包含今天的七个自然日 |
| 三天存在缺失记录 | 三天都填写后才显示平均值 |
| 历史作息能否修改 | 入睡时刻可补记、修改；饮品只追加，不能撤销 |
| 事件同步目标 | 每次选择新项目，或加入已有项目 |
| 加入已有项目的层级 | 每次选择新阶段或新任务；任务指定所属阶段 |
| 事件与事项是否联动 | 日历改动单向更新事项，事项改动不反向更新日历 |
| 事件日期的用途 | 同时作为对应事项的截止日期 |
| 下级没有单独日期 | 沿用上一级截止日期 |
| 删除已同步事件 | 每次询问是否同时删除项目事项 |
| 统计栏位置 | 今日作息和日历顶部都显示 |
| 网页展示方式 | 在当前聊天旁可操作的预览 |
| 预览初始内容 | 可清除的合成示例，和原程序的数据分开 |

同时要求已全部完成的项目从“我的项目”初始列表消失，只在已完成记录中查看。

## 7. 导航合并与浮窗层级

把全部任务、速写本、今日作息合并到“其他功能”浮窗。日历在其他功能上面，左侧顺序最终为：今日计划、我的项目、日历、其他功能。

发现速写本编辑区遮挡浮窗后，调整侧栏与浮窗的显示层级，并实际检查三个菜单入口都能接收点击。

## 8. 桌面构建与原位置升级

0.4.0 的 Windows 程序目录已生成并检查。独立 NSIS 安装器的最后编译步骤受到当前环境限制，没有成功生成对应 exe。曾提供可由使用者在本机运行的生成文件；该文件依赖当时工作区，不作为通用共享工具发放。

使用者要求 0.4 直接覆盖原 0.3，并选择把桌面的旧安装文件移到回收站。实际升级采用原位置更新：备份并校验后，仅替换原程序本体与资源包，原快捷方式仍指向相同路径。版本号核验为 0.4.0，个人数据未改动；没有执行升级后的原生启动验证，也没有修改旧版卸载登记。
